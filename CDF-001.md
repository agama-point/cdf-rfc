## Motivation

Create data format primarily for lightning network and cryptocurrency ATMs / PoS terminals and general data exchange.
This format is primarily for machine-to-machine communication, can be utilized e.g. by NFC technology.

## Conventions

The key words "MUST", "MUST NOT", "SHOULD", "SHOULD NOT" and "MAY" in CDF documents are to be interpreted as described in [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119).

## Status

Each CDF document has one of following statuses:

- **Draft** - work in progress, may change at any time.
- **Proposed** - specification is complete, only fixes are allowed.
- **Final** - specification is implemented and used. Document MUST NOT be changed except for errata. Any other change MUST be done by a new CDF document.
- **Rejected** - proposal was not accepted.
- **Withdrawn** - proposal was withdrawn by author.
- **Replaced** - document is replaced by a newer CDF document.

Status is changed by the author. Change from Proposed to Final requires at least one implementation.

## Specifications

Format is specified in individual CDF documents within this repository. It defines data format for enabling LN transactions via [LNURL](https://github.com/lnurl/luds) and onchain payments using addresses and (legacy) raw private keys.
Currently, specs include [general major type](/CDF-002.md) `cdf`, [minor types](/CDF-003.md) for certain BTC onchain and LN related payloads and [method](/CDF-004.md) of using them in NFC chips with coexistence with legacy records.
