## Abstract

Define how to store CDF records in RFID/NFC chips using NDEF.

## Motivation

For coexistence with legacy RFID records, where the first text record is BTC/LTC private key, a clear way is needed to store both technologies (on-chain and LN) on the same RFID chip.

## Data format

- Each CDF record MUST be stored as separate NDEF record with MIME type (TNF 0x02) as defined in [CDF-003](/CDF-003.md).
- Record payload MUST be UTF-8 string without null terminator and without BOM.
- NDEF message MAY contain also non-CDF records (e.g. URI record).
- Order of records is significant for `cdf/lnpb` records (see Base URL in [CDF-003](/CDF-003.md)) and for non-interactive readers (see Usage). Preferred record SHOULD be placed before other records of the same purpose.

## Usage

- If more than one record is found, interactive ATM/POS MAY let user select record by index (or label if used), e.g. [LNUCD](https://github.com/agama-point/lnucd). Otherwise it SHOULD behave as non-interactive.
- `cdf/lnpb` records are not payment records and MUST NOT be selected by reader, neither offered to user.
- Non-interactive ATM/POS SHOULD use the first record usable for its purpose (e.g. ATM uses pay record, POS uses withdrawal record). This record is not necessarily CDF record (e.g. URI record).

## Legacy records

- Legacy records (e.g. text record with private key, bech32 LNURL in text record) are not standardized and differ between implementations.
- Reader MAY support legacy records in implementation-specific way.
