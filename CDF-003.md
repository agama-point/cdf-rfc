## Motivation

This data format supports various kinds of transactions - Lightning using LNURL and onchain with addresses and private keys. Multiple technologies in one memory unit require clear distinction between them. We introduce first minor types.

## General rules

### LNURL

All `cdf/ln*` records MUST be in plain URL format, not bech32 to save space in RFID chips. In machine-to-machine communication there is no reason to use bech32 format at all. Semicolon in URL MUST be percent-encoded (`%3B`).

With distinguished `cdf/lnp` and `cdf/lnw` records, one memory unit can be used to both receive and withdraw funds.

### URL scheme

Applies to `cdf/lnp`, `cdf/lnw` and `cdf/lnpb` records.

- Generator SHOULD omit `https://` scheme to save space.
- If value (without label) does not start with scheme (`^[a-zA-Z][a-zA-Z0-9+.-]*://`), reader MUST prepend `https://`.
- If value starts with scheme, reader MUST use it as is.
- Generator SHOULD NOT use `http://` except for testing (localhost, private IP address) or `.onion` hosts. Reader MAY reject `http://` URLs.
- Implicit scheme for future minor types is defined by the minor type definition.

### Labels

- Record MAY contain optional label, separated from value by semicolon delimiter `;` (`label;value`).
- Label MUST be UTF-8 encoded (plain ASCII is valid UTF-8).
- Label MUST NOT contain `;`.
- Reader MUST split payload at the first `;` only.
- `cdf/lnpb` record MUST NOT contain label.

### Base URL

- Prefixed records (`cdf/lnpp`, `cdf/lnpw`) MUST be resolved against the last preceding `cdf/lnpb` record. Each new `cdf/lnpb` record replaces the previous one for all following records.
- Generator MUST place `cdf/lnpb` record before records which use it.
- Reader MUST ignore prefixed records without preceding `cdf/lnpb` record.
- Resulting URL is simple string concatenation of base and suffix (not RFC 3986 relative resolution).
- Generator SHOULD write base without trailing `/` and suffix with leading `/`.
- If base ends with `/` and suffix starts with `/`, reader MUST remove one of them. Reader MUST NOT insert `/` otherwise.

## Minor types

|    Mime type    | Description                                     |
| :-------------: | ----------------------------------------------- |
|     cdf/lnp     | Pay URL                                         |
|     cdf/lnw     | Withdrawal URL                                  |
|     cdf/lnpb    | Base (prefix) URL                               |
|     cdf/lnpp    | Prefixed pay                                    |
|     cdf/lnpw    | Prefixed withdrawal                             |
|   cdf/k[coin]   | Private key for [coin] (cdf/kbitcoin - bitcoin) |
|   cdf/p[coin]   | Address for [coin] (cdf/pbitcoin - bitcoin)     |

**cdf/lnp**

- Pay URL
- used to charge satoshis into RFID wallet
- Example: "Wallet1;mywallet.example.org/payurl?id=123"
- Example: "mywallet.example.org/payurl?id=123"
- Example: "https://mywallet.example.org/payurl?id=123"
- Example (testing): "http://192.168.1.10:5000/payurl?id=123"

**cdf/lnw**

- Withdrawal URL
- used to pay on POS/Vending machine etc by RFID
- rest same as `cdf/lnp`

**cdf/lnpb**

- Base (prefix) URL
- Used to save space in other records
- Example: "mycoolnode.example.org/lnbitsinstance"
- Example result: "mycoolnode.example.org/lnbitsinstance" + "/lnpay?someid=123" = "https://mycoolnode.example.org/lnbitsinstance/lnpay?someid=123"

**cdf/lnpp**

- Prefixed Pay
- Pay URL suffix
- Example: "Wallet 1;/lnpay?someid=123"

**cdf/lnpw**

- Prefixed Withdrawal
- Withdrawal URL suffix
- Example: "Wallet 1;/lnwithdraw?someid=123"

**cdf/k[coin]**

- private key for [coin]
- [coin] MUST be full coin name
- value MUST be private key in WIF format
- used for compatibility with POS or ATM for on-chain transactions on offline data storage (eg RFID tag)
- private key is used to spend funds (UTXO) received to address derived from this key
- funds may be on any address type derived from the key (e.g. `1...`, `3...`, `bc1q...`, `bc1p...`), reader MAY derive all of them to find UTXO
- Example: "KwdMAjGmerYanjeui5SHS7JkmpZvVipYvB2LJGU1ZxJwYvP98617"

**cdf/p[coin]**

- address for `[coin]`
- address type is detected by reader from address format (e.g. `1...`, `3...`, `bc1q...`, `bc1p...`)
- value MUST be address only, without URI scheme prefix (`bitcoin:`), coin is already given by MIME type
- Example: "1LoVGDgRs9hTfTNJNuXKSpywcbdvwRXpmK"
